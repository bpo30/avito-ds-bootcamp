# Генерация кандидатов для объявлений услуг

## Состав

| Файл | Назначение |
| --- | --- |
| `solution.ipynb` | Полный воспроизводимый расчёт. |
| `answer.csv` | Сформированные кандидаты. |
| `requirements.txt` | Версии библиотек. |

Данные не включены в репозиторий. Файлы `train.parquet`,
`benchmark_queries.parquet` и `benchmark_items.parquet` должны находиться в
`data/` рядом с корнем проекта.

## Метод

Используются текст запроса, текст фильтров и локация поиска; заголовок,
параметры, ограниченное описание и локация объявления. Категория и фильтры
участвуют в группировке локальной валидации. Цена, рейтинг, координаты,
доставка и ограничения связи не используются: в кандидатогенерации жёсткие
ограничения по ним могут убрать релевантное объявление и снизить Recall@50.

Для каждого запроса строятся четыре списка кандидатов:

- BM25 по заголовку, параметрам и ограниченному описанию;
- символьный TF-IDF по заголовку;
- те же два метода в точной локации поиска.

Списки объединяются reciprocal rank fusion. Заголовок и параметры повторяются
в тексте индекса, потому что для коротких запросов они обычно информативнее
длинного описания. Символьный индекс покрывает словоформы, слитное написание
и небольшие опечатки.

Дополнительно строится item query profile. К тексту каждого объявления
добавляются до восьми запросов из train, по которым это объявление выбрали.
TF-IDF по таким профилям заменяет три последних кандидата лексического top-50.
Размер хвоста выбран по локальной валидации среди 1, 2, 3 и 5 кандидатов.

## Локальная оценка

Используются три group split по нормализованному тексту запроса, категории и
фильтрам. При оценке profile строится только по обучающей части split: запросы
и выбранные объявления из holdout в него не попадают.

| Вариант | Средний Recall@50 |
| --- | ---: |
| Лексический RRF | 0.637182 |
| RRF + item query profile | 0.644239 |

Платформенный Recall@50 этой версии: `0.677555`.

## Воспроизводимость

Установить зависимости командой `pip install -r requirements.txt`, затем
выполнить `solution.ipynb` сверху вниз. Ноутбук фиксирует seed и записывает
результат в `answer.csv`.

## Ограничения метода

Проверенные dense-hybrid и поиск по похожим train-запросам ухудшили метрику,
поэтому в эту версию не включены. Profile меняет только хвост выдачи, сохраняя
сильные лексические кандидаты.
